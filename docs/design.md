# Design

Key decisions and the reasoning behind them.

## DHT layer

### Actor-per-node

Each `DhtNode` is a single-owner actor (`Actor::run`) owning the UDP socket, routing table, pending queries, peer store, and token issuer. The public `DhtNode` handle is a cloneable mpsc sender; external calls (`ping`, `find_node`, `get_peers`, `announce_peer`, `table_snapshot`, `save_state`) become commands answered over oneshot channels. This avoids locks around the routing table and keeps socket I/O single-threaded per node.

Consequences:

- Queries carry a 2 s timeout (`QUERY_TIMEOUT`) enforced both by `recv_with_timeout` and a 1 s pending-query sweep, so dropped packets cannot leak reply channels.
- Keepalive: nodes idle for 10 minutes are pinged (up to 3 attempts) and removed on failure.
- State (node ID + table addresses) is saved every 5 minutes via `spawn_blocking` and on shutdown, and restored on start, keeping node identity and connections stable across restarts.

### Fleet positioning

The crawler starts `node_count` nodes (default 50) with IDs generated by `NodeId::random_discrete_ids`, which spreads first-two-byte prefixes evenly across the 16-bit space. This widens the fraction of the keyspace each node observes, so the fleet sees a much larger share of announce traffic than a single node.

### Routing table

Standard Kademlia with `K = 8`. Buckets are ordered ranges of 20-byte IDs; a full bucket is split only if it contains the node's own ID (and the range is wider than 2), otherwise the insert is dropped. This bounds table growth while staying responsive near the own ID. `closest` does a linear scan with XOR-distance sort, which is adequate at these sizes.

### Tokens

`TokenIssuer` computes HMAC-SHA1(secret, epoch || ip) truncated to 8 bytes, with a 600 s epoch. Verification accepts the current or previous epoch, so tokens stay valid across rotation without a store. The secret is random per process; comparison is constant-time.

### Iterative search

`search.rs` implements one iterative loop shared by `find_node` and `get_peers`: start from the routing table, query up to `SEARCH_WIDTH = 32` candidates in parallel, keep the closest unqueried nodes, and stop after `SEARCH_RETRIES = 4` rounds without improvement in closest-alive distance. `get_peers` results collect trackers with their announce tokens and any peer values; the reader later uses those tokens via the peer-source abstraction.

### Protocol notes

- Transaction IDs are method-tagged (`pn`/`fn`/`gp`/`an` + 16-bit sequence), making responses self-describing.
- Compact node encoding accepts IPv4 (26-byte) and IPv6 (38-byte) records but rejects mixed lists, matching common client behavior.
- Announced port 0 or `implied_port` resolves to the sender's UDP port.
- `PeerStore` keeps at most 64 peers per hash (evicting oldest), serves at most 50, and expires entries after 30 minutes.

## Pipeline design

### Two-stage queues with bounded memory

The pipeline deliberately decouples discovery from downloading:

1. `HashCache` (aggregation): merges repeated info-hash events into counts and flushes in batches. Flushing is size-triggered or time-triggered; on store failure the drained entries are restored to memory, so counts are not lost.
2. `DownloadCache` (work queue): FIFO of `PendingHash`. When full it spills the oldest third to the store's `wait_download` collection; `get_one` drains memory first, then refills from the store. Shutdown flushes remaining entries.

Failed downloads increment `attempts` and return to `wait_download`; after `MAX_REQUEUE_ATTEMPTS = 3` they are dropped, preventing poison-hash loops.

### Fast path

If a hash is already in the torrent index, the reader skips downloading entirely: it increments `announce`, records the day-range hit, and updates stats. This makes repeated announces cheap — the common case in DHT traffic.

### Peer sourcing behind a trait

`PeerSource` (`peers_for(info_hash)`) decouples the reader from the DHT layer. The crawler wires in `SearchPeerSource`, which first answers from `AnnouncePeerCache` (recent announce_peer observations, 16 peers/hash, 30-minute TTL) and otherwise runs a `get_peers` search on the node whose ID is XOR-closest to the target. Tests and the standalone reader substitute trivial implementations.

### BEP-9 download budgets

`Reader` bounds work at three levels: 30 s peer-search budget, 120 s overall deadline per hash, 8 s per peer timeout. Downloaded info dictionaries are verified twice: SHA-1 against the info hash inside `bep9`, and again after wrapping into a torrent file in `handle_content` — mismatched content is dropped, never indexed. `MAX_METADATA_SIZE` (8 MiB) caps piece allocation. A random `-TR4050-` peer ID avoids advertising a distinctive client.

## Search and indexing

- Names are tokenized by `SegMethod`: `none` (whole string), `simple` (all substrings of separator-delimited runs — fine for CJK), or `rmmseg` (reverse-maximum-matching against the bundled `dicts/words.dic`; ASCII runs pass through).
- MongoDB stores `name_array` under a text index; search is a `$text` query. `MemoryStore` matches documents containing all whitespace-separated query tokens against the name words plus tokens.
- `TorrentDoc` stores the file list; the API returns files sorted by size. `/api/search` accepts an optional `files=N` parameter to limit the list per result; `/api/index` and `/api/today_top` always return every file. `/api/today_top` accepts an optional `limit=N` parameter (default 50).

## HTTP layer

- axum router with JSON API routes (`/api/search`, `/api/today_top`, `/api/stats`, `/api/index`).
- `ResultCache` is a TTL map (10 minutes, 1000 entries, evicts the oldest half when full). Search results are served only fresh; today-top and stats are refreshed by a background task and served stale on store failure.
- Today-top falls back up to 2 days back when the current day has no daterange data.
- All query parameters are validated: keywords trimmed, page numbers clamped to ≥ 1, info hashes checked with `hex::is_hash`.

## Configuration

TOML with `deny_unknown_fields` and per-section defaults; `load_or_create` writes the default file on first run. Section defaults intentionally mirror the values of the original dhtcrawler2 project (ports 6776.., 50 nodes, 300-entry hash cache, port 8000).

## Testing strategy

- Unit tests inline in most modules (codec roundtrips, routing-table behavior, cache eviction, store semantics).
- Integration tests in `tests/`: real UDP node pairs (`tests/dht_node.rs`), axum router requests via `tower::oneshot` (`tests/httpd_httpd.rs`), and an end-to-end BEP-9 flow against a fake peer in `tests/pipeline/`.
